# 第一期 MVP 实施方案

> 版本：1.4，2026-09-19。本文件是实施文档，只定义做什么、顺序、接口与验收；编写本文时未启动任何新开发。
> v1.4 修订（负责人评审）：残锁不做并发自动接管——运行中遇残锁停止并告警，清理只在启动前置恢复步骤（确认无存活进程后）执行，普通加锁/释放仍自动（5.4）；`session/flush` 监听器与持久化排水并行执行，收到通知≠已落盘——补读以"读到本轮目标 seq"为完成判定并保留待补读状态，去重键加入日志代际 `(sessionId, generation, seq)`（5.5/步骤 6）；任务身份不支持会话中途切换——一个会话仅归属一个任务，换任务即新建会话（"继续"可选）（5.6/步骤 6）；健康检查改为按实例核对自己应加载的产物（插件查激活，Memory/Skill/配置查版本与加载证据，候选在其运行实例或会话绑定时核对），控制文件损坏时空集合启动**保留既有安全配置（含日志上传关闭）**（步骤 4）。
> v1.3 修订（负责人评审）：恢复动作区分**撤销试用**（baseline 不动）与**回退正式发布**（坏版本入隔离清单、previous 置空、重复回退不换回坏版本）（5.4/5.6）；名额检查与占位合并为 `bindForTask` 单次锁内操作，锁实现为 O_EXCL 锁文件（环境无 flock 命令）（5.4/5.6）；预算补"预占→调用→结算/未知保留占额"与 reconcile 补账（第 7 节）；任务身份前置为会话建立时的"新任务/继续"入口，事后归并（人工认领制，暂不做相似度匹配）只修统计不改执行绑定（5.6/步骤 6）；启动健康检查关联 bootId 并核对预期集合实际激活，控制文件损坏以空受管理集合启动、不声称回退（步骤 4）；采集增加事件级去重键 `(sessionId, seq)`、`session/flush` 唤醒、启动补扫与崩溃恢复测试（步骤 6）。
> v1.2 修订（负责人评审）：发布状态与试用状态合并为单一控制文件 `control.json`，活动试用绑定发布编号与候选摘要，任何发布/恢复动作必然使旧试用失效（5.4/5.6）；绑定入口先按任务查既有绑定再查期限/名额，占位与绑定为同一次原子写（5.6）；只读探针改在无其他写入者的授权副本上验证，并发场景允许首读为前缀、以 flush 后完整不重不漏为准（5.5、步骤 6）；Jev 接入验证增加预登记要求——样本集、通过条件与"不确定"处理须在测试前冻结留痕（8.4、步骤 7）。
> v1.1 修订（负责人评审）：明确工作进程读取 Harness 记录的具体路径（5.5）；试用限制增加真实控制入口（5.6）；发布状态改为单文件单写入函数（5.4）；修正 `session/event` 落盘语义（4、步骤 6）；成本记录提前到首次模型调用、证据合同探针按"当时已实现能力"分两处验收（步骤 3/8/10）；区分"对照证据缺失→人工审查分支"与"必需安全/运行证据缺失→拦截"（步骤 8/9）；Jev 按负责人指示纳入第一期轻量审计（D-062，见 8.4）。

## 2. MVP 最小闭环与边界

### 2.1 唯一闭环

```text
真实代码任务（PTC + deepseek-v4-flash，官方网页）
→ 最小采集（增量读取、来源隔离、任务归并、结果标记）
→ 人工触发分析（Flash 主分析 + Jev 轻量审计） → 问题卡片（≥3 个独立真实任务支持，或如实记证据不足）
→ 人工确认事实 → 冻结验证计划与可用独立材料
→ 选择节点：Memory / Skill / 配置 / 插件 中最小有效改动
→ 生成候选（插件类型走创造模式，仅装测试 profile；三版与预算上限）
→ 证据合同捕获器就绪并过探针 → 真实关键步骤新旧对照 + 适用离线检查
→ 冻结实际产物 → 干净实例复验 → 人工批准限定范围试用
→ 试用（≤5 个实际任务或 7 天，先到为准；绑定入口强制） → 到期复盘
→ 人工保留 / 恢复 → 持久化与恢复演练
```

流程跑通与真实有效分别验收。任何一步证据不足就如实标记，不用外围功能或自编题补成成功。

## 3. 模块与文件职责

架构约束：自进化逻辑集中在独立模块；Harness 侧只有薄接入；恢复路径独立于插件存活；不修改上游核心，进化判断不散布到各层。

```text
packages/
  evolution-probe/        # 控制插件（薄接入层）。宿主：session/event+flush 唤醒、结果标记入口、
                          #   任务身份入口（新任务/继续）、人工触发、按需拉起工作进程、
                          #   新会话版本绑定与试用资格检查（bindForTask 单次锁内完成，见 5.4/5.6）、
                          #   状态写读；客户端：composer.dock 状态标记。
                          #   不做分析、不生成候选；控制状态只经统一写入函数变更，不自行拼装文件。
  evolution/              # 独立进化模块（纯库，无 Cordis 运行时依赖）：任务归并、经验整理、
                          #   发现分析编排、Jev 审计客户端、验证计划冻结、成本账本、试用记账、
                          #   控制状态原子读写（5.4）。定义 SessionSource 只读端口（5.5），
                          #   读取能力由工作进程侧适配器注入；库自身不接触日志文件格式。
  evolution-capture/      # 捕获器插件（小）：llm/stream recorder、compaction/turn 事件 → JSONL+manifest。
                          #   只在首个真实机会选定边界后按需实现（见 8.2），不预建全事件抓取。
scripts/
  start.mjs               # 外部启动器：读 state/control.json 的 baseline 启动官方网页，健康检查含
                          #   受管理插件实际激活；失败时经统一写入函数恢复上一基线（seq+1，
                          #   活动试用同时失效）后仅重试一次；负责清理残留工作进程。
  evolution-worker.mjs    # 按需工作进程入口（单实例锁；环境变量允许清单；异常退出标中断不自动重试）。
                          #   含 SessionSource 官方适配器：装载最小官方服务环境提供只读读取（5.5）。
  run-candidate-probe.mjs # 创造模式候选探针（里程碑零任务四；独立 DSH_HOME/测试 profile）。
  test-startup-recovery.mjs # 启动/运行故障恢复自检演练。
state/
  control.json            # 控制状态单文件：seq、baseline、previous、activeTrial（绑定发布编号与
                          #   候选摘要、期限、名额占用）、批准/恢复记录。含任务/会话标识等运行时
                          #   数据，不入 Git；脱敏发布/批准记录另存 artifacts/ 并入 Git（5.4）
  control.lock            # 控制状态互斥锁
  worker.lock / worker-status.json   # 工作进程单实例与真实状态（运行时数据，Git 外）
evolution-private/        # Git 外，权限 0700：captures/、manifests/、costs.jsonl、budgets/、derived/
                          #   （经验信号、问题卡片、验证计划、候选记录、试用复盘材料、恢复明细）
artifacts/milestone-0/ddefc45/   # 新版验收证据（旧 README 保留为 47f9438 历史证据）
vendor/dsh-0.1.6/         # 目标上游 checkout（Git 忽略；不提交依赖与构建产物）
```

进程关系（均为既定设计，不新建平台）：主网页进程（带控制插件）→ 按需 `evolution-worker.mjs`（重活）→ 隔离测试实例（官方启动器拉起，创造模式/对照/复验）。控制插件以 `child_process` 按需拉起工作进程并把 PID 记入 `state/worker.lock`；外部启动器在自身退出、恢复、清理时按 PID 终止残留工作进程。工作进程与控制插件之间只通过本地状态文件与请求文件交互。

### 5.3 写入协议

捕获按合同第 2 节：先写 input，顺序追加 output，原子发布 complete manifest；崩溃/超限保留 incomplete，不截断称完整。成本按合同第 4 节 `costs.jsonl`（start/finish/reconcile，operationId 去重，未知用量 null 不记 0）。删除：清理派生正文与受管理副本，保留最小脱敏删除记录；不据此声称 Git 历史已删。

### 5.4 控制状态（发布与试用）：单文件、单写入函数、核心不变式

- **单文件 `state/control.json`**（原子替换），同一份数据同时携带：`seq`（发布编号）、`baseline`（正式基线集合及摘要）、`previous`（上一基线）、`quarantine`（坏版本隔离清单：hash+原因+时间，回退目标永不从中选取）、`activeTrial`（null，或 `{trialId, candidateId, releaseSeq, candidateDigest, 适用条件, startedAtUtc, deadlineUtc, enrolled[], status}`）、批准与恢复记录（脱敏摘要）。**发布状态与试用状态不分开保存**，从结构上消除两文件各自更新造成的错配（"发布已换、试用没写上"或"已恢复旧版、试用仍生效"都不可能出现）。
- **核心不变式**：活动试用仅当 `activeTrial.releaseSeq === 当前 seq`、且 `candidateDigest` 与实际加载的候选产物摘要一致、且 `status === active` 时有效；任一不满足即视为**无活动试用**，绑定回落基线并报告原因。任何发布动作都使 seq+1，因此**正式采用、撤销试用与故障回退都必然使旧试用失效**；候选产物被替换或篡改时摘要不匹配，候选被禁止生效。
- **唯一写入实现**：`packages/evolution` 的控制状态写入函数——校验输入（不可变产物 sha256、人工批准记录或故障恢复依据）→ 组装新 `control.json` → 写临时文件 + fsync + 原子 rename。**四类发布动作都经它**：**正式发布**（baseline←新集合、activeTrial←null、seq+1）、**试用启用**（baseline 不变、activeTrial←绑定当前 seq 与候选摘要、seq+1）、**撤销试用**（试用候选技术故障：activeTrial←invalidated 并记原因、**baseline 不动**、seq+1——正式基线继续服务，不得误退 previous）、**故障回退**（正式基线产物故障：旧 baseline 入 quarantine、baseline←previous、**previous←null**（坏版本不得再成为回退目标）、activeTrial←null、seq+1；previous 为空或其 hash 已在隔离清单 → 拒绝执行并停机交人工——重复回退永远换不回坏版本）。绑定与占位由 `bindForTask` 在同一次锁内完成（5.6），不 bump seq。
- **受控调用方**：控制插件（正式发布、试用启用、绑定）与外部启动器（撤销试用/故障回退），互斥经 `state/control.lock`——**锁实现为 O_EXCL 锁文件**（独占创建、写入 pid、自动获取/释放），不依赖 `flock` 或其他外部命令。**残锁不做并发自动接管**：超时后诊断 pid——存活则稍后重试；已死或损坏则抛 `StaleLockError`、该操作停止并告警、**不自动删锁**（两个进程同时处理残锁时，自动删除可能误删对方刚取得的新锁）；残锁清理只在启动器拉起子进程**之前**的恢复步骤执行（核对全部 pid 已死才删除，发现存活 pid 则中止启动交人工）。候选、工作进程、模型一律无调用权；控制插件也不自行拼装或直接改写该文件。
- **崩溃规则**：rename 前崩溃 → 文件仍是旧版，本次动作未发生；rename 后崩溃 → 新版已生效。以文件内容与 seq 为准，不做跨文件推断。启动器恢复后受影响任务保持暂停并提示用户（既有要求不变）。
- **Git 边界**：`control.json` 含任务/会话标识等运行时数据，不入 Git；每次发布/批准/恢复的脱敏记录写入 `artifacts/` 对应证据目录并提交（满足 D-054 版本清单留痕，不把运行时标识提交进 Git）。

### 5.5 会话读取路径：SessionSource 端口 + 工作进程内最小官方服务环境

明确选一种方式：**主选 = 工作进程装载最小官方服务环境**（技术设计第 4 节既有选择"需要 Harness 服务上下文时在独立实例加载官方服务"）；备选仅在主选被证不可行时启用（见下）。禁止任何一方自行解析日志文件格式——绕过官方迁移与读取保证判定为实现缺陷。

- **端口定义**：`packages/evolution` 定义 `SessionSource` 只读端口，仅暴露 `stat / list / open(id,'read') / handle.read(offset,length) / close` 五类调用。纯库只依赖此端口（构造注入，无端口实现则单测无法构造），从结构上杜绝"临时自己解析日志"。
- **提供方（主选）**：`scripts/evolution-worker.mjs` 内的薄适配器——新建 Cordis `Context`，**仅装载目标版本官方会话存储/持久化服务包**（来自 `vendor/dsh-0.1.6` 固定提交；具体可独立装载的导出以目标版本源码/`cordis_inspect` 实机核对为准），不装载 app-boot、plugin-manager、session-log-deepseek 等任何含写路径或上传路径的服务。
- **读哪个目录**：主运行环境的 sessions 根目录，由外部启动器经环境变量**显式传入**（允许清单项，如 `EVO_SESSIONS_ROOT`），工作进程不自行猜测默认路径；授权旧日志副本验证场景（步骤 1）指向副本目录。
- **如何保证只读**：适配器只调用 `open(id,'read')`，模块内不得出现 `create()` 或写打开（代码评审硬项）；工作进程数据目录层面只挂读取所需路径。
- **验收探针（步骤 6）**：只读性验证在**无其他写入者的授权副本**上进行——工作进程完整补读一轮，副本目录前后文件清单+哈希**零变化**（新增/修改/删除均不得出现）；旧格式副本只读打开仅在内存迁移、源文件不变。真实并发场景中主 Harness 可能正在正常写日志，不以"目录未变化"作为真实目录上的验收条件。
- **备选（仅当主选被证不可行，以步骤 1 的 P1 探针结论定案并留证据）**：控制插件在主进程内实现同一 `SessionSource` 接口，经本地 IPC 提供给工作进程。两种方式端口相同、调用方代码不变。

### 5.6 试用控制入口：bindForTask 单次锁内完成，不依赖分析进程存活

- **任务身份前置**：会话建立（首条消息前）经控制插件的最小入口确定身份——默认"新任务"（新建 taskId），或用户选择"继续 <最近任务>"（复用 taskId，用于跨会话重试）。**MVP 不支持会话中途切换任务**：一个会话从建立起归属且仅归属一个任务；开始新工作 → 新建会话，继续旧工作 → 新建会话并选"继续"（消除会话内区间归属与版本中途切换问题）。绑定与名额计数都以该 binding-time 身份为准；跨会话重试未经入口按新任务绑定，操作者**事后人工认领合并只修统计与计数**（MVP 不做相似度匹配），不改已发生的执行绑定、不追改会话实际使用的版本。
- **执行点 = 新会话版本绑定入口**。控制插件调用 `bindForTask`（5.4 锁内单次完成，杜绝"先查后写"竞态）：
  1. **先按 taskId 查既有绑定**。已有 → **复用该任务已绑定的版本，不新增名额、不中途换做法**——第五个任务换会话重试（经"继续"入口）不会被名额已满切回旧版，也不会重复占用名额。
  2. 无既有绑定且存在**有效**活动试用（按 5.4 不变式校验：seq 匹配、候选摘要匹配、status=active）且该会话符合预先批准条件 → 同锁内检查 `now < deadlineUtc` 且 `enrolledTasks < 5`，通过则**在同一次原子写中**追加绑定记录（taskId、sessionId、boundVersion、enrolledAtUtc）并绑定候选版；任一不满足 → 绑定基线并记录原因（expired / quota-full / condition-mismatch / trial-invalid）。
  3. 无有效活动试用 → 按基线绑定。
- **占位与绑定是同一次原子写**：不存在"占位后、绑定前"的中间态。崩溃要么发生在原子替换之前（无记录，下次同一任务按首访路径重新判定，不重复扣名额），要么发生在替换之后（绑定记录已在，同任务复用）。
- **并发**：判定与写入在同一次锁内原子完成；两个新任务同时到达时，只有一个能拿到第五个名额。
- **持久与重启**：期限、名额、既有绑定都在 `control.json`；应用重启后控制插件从文件恢复限制，**过期默认基线**，不依赖工作进程或任何分析进程存活。到期报告可以延后生成，但过期限制即时生效——不会出现"账上到期了，实际还在使用"。
- **故障停用区分两类**：试用候选技术故障 → **撤销试用**（baseline 不动，下一任务回基线，受影响任务暂停提示）；正式基线产物故障 → **故障回退**（5.4，坏版本入隔离）。都不走绑定入口的静默改绑。
- **到期动作**：绑定入口发现过期 → 停止纳入并把试用标记 `expired`（等待复盘）；不自动成功、不静默续期，续期 = 新的试用启用动作（重新绑定 seq 与期限，留痕）。

内容：冻结步骤 3 候选（源码+配置+依赖记录+sha256）；先静态核对包清单/入口/配置层可被官方加载器解析；干净测试实例安装并跑生命周期；按冻结验证计划复验适用离线检查；经统一写入函数写入测试用控制状态并跨重启确认。实现 `scripts/start.mjs` + `test-startup-recovery.mjs`：**启动前置恢复步骤**（拉起任何子进程之前，此时不存在本环境写者）核对各锁文件 pid，全部已死才清理残锁，发现存活 pid → 中止启动交人工。随后读 `control.json`，若损坏 → **不以猜测基线启动**：以"空受管理集合"启动（仅官方默认 bundles，**保留既有安全配置，含 `session-log-deepseek.enabled=false`——空集合指进化产物，不回退安全配置**），状态置 paused 等待人工修复——此时不存在可信基线，不得声称"已回落基线"；正常路径生成 `bootId` 随 env 传入，自检覆盖 profile 启动失败时按故障对象选恢复动作（**试用候选故障 → 撤销试用，baseline 不动；正式基线故障 → 故障回退**，见 5.4）后仅重试一次；成功信号 = 子进程退出状态 **加** 健康记录：控制插件按 `bootId` 写 `state/launcher-health.json`——**按实例核对各自应加载的产物**：插件类查实际激活，Memory/Skill/配置类核对版本与加载证据（生效摘要与控制文件预期一致），试用候选在其运行的实例或绑定会话建立时核对，不强求主实例激活；bootId 不匹配本次启动的旧心跳直接忽略——覆盖"网页已启动但另一受管插件激活失败"（心跳在但集合不全，判败）与"控制插件死亡"（无心跳，判败）两类场景；人为坏插件覆盖进程非零退出与仅告警两种情况；启动成功后注入运行故障验证外部恢复不依赖控制插件；演练"进程仍可运行时的插件故障"：受影响任务先暂停、坏插件停止作用后提示用户，不只切新任务清单；确认恢复不自动重放中断工具调用，未知退出保留诊断交人工。
验收：冻结产物结果单独记录（不用开发运行冒充）；恢复路径在控制插件死亡时仍存在；恢复后受影响任务保持暂停并提示；**恢复动作使活动试用失效并有留痕**；两次失败明确退出不无限重启；控制状态单文件在人为中断写入过程后仍完整（旧版或新版，无撕裂）。
失败动作：启动器无法在坏配置下恢复 → 不进入真实候选发布（G8）；候选不能干净实例安装/复验 → 不允许发布（G5）。

### 步骤 6：最小采集（L）——里程碑一前半

内容：`packages/evolution` 实现——**增量读取**：控制插件监听 `turn/end` 置脏标记（记下本轮**目标 seq** = 已见最新 `turn/end` 的 seq）并监听 `session/flush` 作为补读唤醒之一——**flush 的各监听器并行执行，收到通知 ≠ 已落盘**，不得据此认定最终读完成；工作进程经 SessionSource（5.5 主选方案已在步骤 1 的 P1 探针定案）`stat/list` 发现修订、`open('read')` 补读、关闭句柄；**完成判定**：某轮补读只有读到 ≥ 该轮目标 seq 的事件才判完成，暂读不到 → 保留待补读状态等下一次唤醒；另有**启动补扫**兜底——worker 每次启动对所有"游标落后于当前 revision"的会话全量补扫。**读取进度只在成功补读后推进**。**幂等写入**：经验记录以事件为原子、携带稳定去重键 `(sessionId, generation, seq)`（**含日志代际**，防 V3 迁移重排 seq 后与旧记录混淆），追加前查该会话该代际已写末位 seq 只追加增量，读取端按键兜底去重——"写完经验、未推游标就崩溃"后重启补扫不重不漏。派生经验只存引用（源代际、seq 区间、脱敏摘要），不复制对话库。**来源隔离**：每条记录自创建标 purpose（真实任务/人工练习/内部研究各环节），内部研究不进真实样本。**任务身份与归并**：会话建立时经最小入口确定"新任务/继续"（供 5.6 绑定与计数使用；**不支持会话中途切换**，一个会话仅归属一个任务，换任务即新建会话）；同一工作跨轮次/跨会话重试经入口归并为一，未经入口的重试由操作者事后**人工认领合并**（只修统计，不改执行绑定，MVP 不做相似度匹配）；`turn/end` 数不作任务数；归属不明先不计数。**结果标记**：F-02 通道接入并关联任务/版本/步骤。**真实状态**：六态状态机接入控制插件（记录中/正在分析/正在测试候选/等待确认/新版本观察中/已暂停），来源真实后台状态文件。discovery 等模型阶段沿用步骤 3 已交付的成本账本。采集失败不影响正常任务（监听异常只丢本次，可按修订补读）。
验收：真实会话结束后派生经验可回查原始 V3 日志一致；**立即补读与 flush 后补读的结果呈前缀关系**（立即补读允许只见到较短前缀；flush 屏障完成并补读后结果完整、不重不漏、游标只推进到已确认位置）——不以两次结果相等为条件；**崩溃恢复测试通过**（写完经验未推游标即中断 → 启动补扫 → 不重不漏）；SessionSource 只读探针（授权副本零变化）通过；身份入口可用、绑定前必有 taskId；认领合并修统计不改绑定、有留痕；人工练习/内部研究不出现在真实统计；结果标记与任务关联；采集故障注入不阻塞会话。
失败动作：采集干扰任务 → 先修隔离与补读路径（G11）；P1 定案不可行且备选也不可行 → 停止重评架构。

## 7. 时间与消耗上限机制

- **机制先于数值**：任何自动尝试启动前，在 `evolution-private/budgets/` 写入登记（attemptId、stage、wallClockLimitMs、调用/token 上限、覆盖范围、startedAt），未登记不得启动。调用生命周期为**预占 → 调用 → 结算**：每次调用前 `reserve` 预占保守估计的用量（预占后任一上限触达即记 stop 并停止调度——最后一次请求不得远超剩余预算）；调用后 `settleReservation` 结算，已知用量释放多余占额，**未知用量保留占额、不释放成零**，取消的调用不释放占额（提供方可能仍计费）；账单后续到达时以 `reconcile` 记录补账（关联 operationId，不改原记录）。达到任一上限：取消在途请求、清理实验进程、保留已有记录、标 `timeout`/`budget_exhausted`、等待人工，不自动开下一版。
- **数值确定节点**：具体限额在首次试跑前由操作者填入登记表并留痕（D-044 禁止本文臆定数值）。步骤 3 的候选探针是第一个必须登记的尝试；步骤 7 的每轮分析（含 Jev 调用）、步骤 9 的每次候选尝试、步骤 10 的试用预算各自登记。
- **固定值**（合同第 3 节）：试用 ≤5 个实际任务或启用后 7 天，先到为准；同问题 ≤3 串行版本；这些不在试跑前可调低不可静默调高，调整留痕。**试用期限与名额的执行点在新会话版本绑定入口（5.6），不依赖定时器或分析进程存活**。
- **成本账本**：`costs.jsonl` 自**步骤 3 首次模型调用**起生效（先于任何分析功能）；阶段覆盖随步骤推进（步骤 6 起含 discovery，步骤 9/10 起含 generation/offline-check/trial-observation/review）；Jev 作为独立 provider/model 记账。失败重试计入；usage 未知记 null/unknown 不记 0；缓存与推理 token 不重复相加；并发各调用时长与墙钟分开。

## 8. 关键选择节点与无合格机会的处理

### 8.1 首个候选类型（不预先指定）

选择时机：问题卡片经人工确认、验证计划冻结之前。决策顺序（D-055）：在 Memory、Skill、配置、上下文/检索策略、插件中选择**足够解决该问题的最小改动**——文本/配置能解决则不建插件；需要改变执行机制、工具或跨任务流程时才用创造模式生成标准插件。记录选择理由与被否选项。首个真实候选类型由此节点决定，本方案不预设，也不把上下文删减当必做案例。

### 8.2 捕获边界（先一条真实路径）

选择时机：同 8.1。规则（合同第 1 节）：只实现所选机会真实需要的边界；`llm/stream` recorder 只证明拦截点输入，需比较压缩保留策略时必须另捕获选取发生前的可见 surface（该前置入口尚未核实，未核实前该类策略标 unsupported，不得用摘要请求冒充）；检索、Skill 选择、工具执行同理。无合格捕获路径的问题 → 改选其他机会或记"当前无法对照"（并走步骤 9 判定分支，不一定终止）。

### 8.3 无合格机会时

问题不足三个独立任务支持 → 如实记证据不足，继续收集；30 个带结果标记任务到达 → 正式复盘（继续收集/调整发现方法/暂停项目，记录理由，不降标准、不自动判失败）。不虚构发现、不用人工练习补数、不用扩建外围功能替代研究进展。

### 8.4 Jev：第一期轻量审计（D-062，负责人 2026-09-19 指定纳入）

调研结论（官方文档，2026-09-19）：Jev 是 TypeSafe 的"System One"模型——不做文本生成，对 typed 问题直接返回结构化判定：Choice（选项+概率+置信度）、Score（rubric 评分+置信度）、Noul（0～1 真假判断）；原子问题并行隔离评估，追加问题几乎不增延迟；提供 JS SDK。官方文档无专门的数据处理/隐私页面（仅 legal 条款），故发送范围必须按本项目授权边界核对。

- **角色（轻量审计，不裁决）**：①步骤 7 发现阶段的批量初筛信号（三类样本分组、疑似重复、用户纠正、规则冲突）；②问题卡片的证据-结论一致性原子审计；③步骤 10 试用复盘报告的一致性审计。复杂根因与改法仍由 Flash 分析模型提出；最终采用由验证与人工决定，Jev 无裁决权、不改验收标准。
- **接入验证先预登记（防"测完凭感觉宣布可以"）**：测试开始前，把三样东西写入 `evolution-private/derived/jev-validation/` 登记并冻结：①**样本集**——从本地授权脱敏材料抽取的固定样本，每条带人工核对的标准答案（覆盖失败/低效成功/高质量成功三类与未知类别；数量与抽样方式在登记时写明）；②**通过条件**——初筛与审计两个用途分别的准确率/一致率下限、漏判上限、不确定率上限、成本与延迟上限（数值由操作者登记时填写，本文不臆定，同 D-044 纪律）；③**"不确定"处理**——Jev 置信度低于登记阈值或判为未知类别的输出计为"不确定"，不算对也不算错，一律回退 Flash/人工路径，不硬套判定。测试结果只与预登记条件比对；不通过或事后想改条件即记为未通过，改条件 = 重新登记新一轮验证，不得用同一批结果换门槛宣布通过。
- **接入闸门（沿 D-056/D-061）**：本地授权脱敏样本核对准确率、漏判、成本、延迟；记录模型版本；保留未命中样本抽查与未知类别入口；**发送范围先核对并获负责人确认**——仅发送脱敏派生片段，原始日志、密钥、完整模型请求/响应不外发；未核对前不外发（G13）。
- **回退**：验证不过或范围未确认 → Flash-only 流程，主线不阻塞；审计结果永远只是卡片/报告的附属材料。
- **原子问题设计**：按官方指导拆成"专家几秒可判"的原子问题，权重组合在代码中完成，不在提示里求总分。

### 8.5 其他可选实验

Skill 委派子 Agent、可恢复上下文省略：只能作为 8.1 节点上的候选实验，且须检查对用户约束/权限/未完成事项的影响。任何新提供方（含未来替换 Jev 的服务）接入同样须核对数据发送范围与授权。

## 9. 停止条件与执行闸门

全局停止：任一下列表闸门失败；三版耗尽；单次尝试超限；试用到期；隔离泄漏（测试影响主 profile/真实会话）；**必需运行/安全检查证据缺失**（对照类证据缺失不属全局停止，按步骤 9 判定分支交人工审查）；对照结果矛盾。停止后一律"保留记录 + 等待人工决定"，不自动重试、不自动续期、不静默重置计数。

| 闸门 | 失败后的动作 |
|---|---|
| G1 官方固定版本不能构建/启动 | 停止，先修环境 |
| G2 外部标准插件不能承载会话监听 | 停止，重评"不改核心源码"边界 |
| G3 状态标记不能稳定显示 | 退回最小官方界面位置 |
| G4 创造模式无法在独立进程完成候选生命周期 | 停止，不建候选管理系统 |
| G5 标准候选不能干净实例安装/复验 | 不允许正式发布 |
| G6 V3 读取或旧日志迁移失败 | 保留旧版与原数据，停止切换运行基线 |
| G6b 测试/试用影响主 profile 或已有会话 | 停止试用，先修发布作用域 |
| G7 证据合同探针①～④任一未通过 | 不进入首次真实对照 |
| G8 外部启动器无法在坏配置下恢复 | 不进入真实插件发布 |
| G9 尝试超限不能真实停止 | 先修停止路径 |
| G10 文件撤销覆盖后续修改或缺证据仍撤销 | 先修撤销边界 |
| G11 采集干扰正常任务 | 先修隔离与补读 |
| G12 试用记账/截止/占位可被绕过，或控制状态错配（seq/摘要/状态不符）仍允许候选生效 | 先修闸门再继续试用 |
| G13 Jev 发送范围未核对或接入验证未通过 | 不向该提供方发送数据，回退 Flash-only，不阻塞主线 |
