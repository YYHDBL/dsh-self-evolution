## 实施文档应该交付什么

围绕一条最小闭环列出文件/模块职责、真实接口、数据写入与版本关系、实施顺序、每步可执行验收、时间/成本上限设置和停止条件。用当前仓库核实实际状态，不能把设计中的目标当成已实现接口或已通过测试。

自进化逻辑集中在独立模块；Harness 侧只保留少量接入和状态展示，恢复路径独立存活。不修改上游核心，不把进化判断散布各层，不建设新办公平台。

先完成必要兼容性和运行探针，接最小采集，再人工触发真实机会发现。发现范围含失败、低效成功及成功模式。首个真实候选类型尚未预先指定；实施方案写明选择节点及无合格机会时的处理，不虚构发现，不强行把上下文删减当必做案例。

候选前冻结验证计划；捕获器从实际调用取输入，不由模型补写。首次真实对照前落实证据合同的必要探针；不能捕获的边界标 unsupported。最终产物适用离线检查通过，经人批准限定范围试用；实际效果不足就报告不足。

Memory、Skill、配置、插件是允许范围，不要求第一期全做。Jev 是可选初筛/批量评价实验，未实测，不阻塞流程；没有 Jev 时使用现有分析模型。新提供方数据发送须核对授权范围。

## 不应被重新设计或默默放宽的要求

- 三个独立实际任务支持重复机会；同任务跨会话重试算一个，人工先指出不计自主发现。
- 同一问题最多三版，每次时间和消耗有上限；实际成本含失败重试，未知不填零。
- 默认试用五个实际任务或启用后七天，先到为准；截止复盘不等于成功，不自动续期。
- 用真实关键步骤对照和后续试用，允许按条件完整重跑；不强制每个改动做统一五层整任务考试。
- 不以自编题、模型自评分或单次成功宣称真实有效；独立材料暴露后的处理与来源记录遵守合同。
- 冻结并绑定实际产物版本；限定新会话范围，已有会话不被热更新污染。
- 明确技术故障暂停及恢复；文件自动撤销保护后续修改；不可撤销外部操作逐次批准。
- 原始敏感证据在 Git 外，最小外发与可删除；新版附带日志上传关闭及验证仍待落实。
