> 版本：1.6，更新于 2026-09-19；依据决策 D-042 至 D-060。以下是新版待执行验收要求，旧版证据不能代替新版结果。

> **执行要求：** 开发时按测试先行逐项完成；任何一项未通过，先修正架构，不继续建设外围功能。

本计划保留插件接入、隔离与恢复探针，它证明一种改动路径可用，不意味着每次进化必须生成插件。D-055～D-057 的真实关键步骤对照、文本/配置改动与有限试用在后续里程碑完成；Jev 不作为前置依赖。

**目标：** 用最少代码证明第一期依赖的五个脆弱连接点真实可用。

**结构：** 一个最小标准插件包、一个外部启动脚本、一个独立测试脚本和一个证据目录。暂不实现经验分析、问题卡片、完整账本、自动定时分析和正式发布流程。

**目标技术基线：** Node.js 24、目标源码声明的 pnpm（当前为 `11.7.0`）、DeepSeek Harness `ddefc45fbc7f8e46dd73185e68295696d1297887`（`0.1.6-alpha.2`）、DeepSeek-V4-Flash、官方网页界面。项目根工具链与上游工具链分别记录，不因本次文档更新自动修改包配置。

**实际状态：** 当前 `vendor/deepseek-harness` 仍在旧提交 `47f9438`；最新源码已 fetch，尚未切换、安装或构建。先在独立 checkout、构建目录和 `DSH_HOME` / profile 验证，见[上游兼容性核查](../research/2026-09-19-harness-upstream-compatibility.md)。

## 1. 完成定义

必须同时拿到以下五项实际证据：

1. 官方网页界面能通过项目启动命令启动，并加载最小控制插件；
2. 完成一个真实会话后，插件保存包含会话标识、日志格式和结束事件位置的记录，并通过官方只读 handle 补读核对；
3. 网页始终显示“自进化：记录中”，插件停止后标记消失；
4. 独立 Harness 进程能使用 Flash 创造模式生成标准候选 bundle，并通过 Plugin Manager 仅在测试 profile 安装、运行和停止；
5. 冻结标准候选能在干净实例重新验证并跨重启加载；启动失败及明确运行故障时，能停止受影响任务/实例，由外部启动器恢复上一份启用清单。临时文件演练证明只撤销归属明确且无后续改动的变更。

独立候选试跑同时验证时间和消耗上限：达到任一上限即停止并保留记录，等待人工决定。具体限额在试跑前写入记录，不使用无限等待作为默认值。

任何一项只能靠修改官方核心源码完成，里程碑零判定失败并回到架构评审。

## 3. 任务顺序

### 任务一：固定可运行基线

1. 保留现有 Git 仓库、旧 checkout 和 8 月证据；创建目标 SHA 的独立 checkout，不把构建产物或依赖作为研究源码提交；
2. 检查 Node.js 满足官方要求，分别记录项目与目标上游的包管理器版本；
3. 在目标 checkout 安装其锁定依赖并完成官方构建，不复用旧版 `node_modules` 或 `lib`；
4. 在目标 profile 明确配置 `session-log-deepseek.enabled=false`，核查实际生效配置；用本地替身/请求构造检查确认带 sessionId 的请求不含 `dsh_session_log`，不向真实端点发送测试日志。之后使用独立 `DSH_HOME` / profile 启动网页，完成一次不带自进化插件的最小会话；
5. 在证据目录新增带目标 SHA 的验收记录，保留 `README.md` 中旧版记录，不改写成新版已通过；
6. 对授权的旧日志副本验证官方只读迁移到 V3，记录源格式与新格式引用，确认不沿用旧 seq 和偏移。

验收：固定源码可以独立启动。失败时只修环境，不创建项目插件。

### 任务二：标准插件装载与会话记录

1. 先写一个最小测试，使用 Cordis 测试上下文发送 `turn/end` 事件，断言探针只追加一条记录；
2. 适配 `packages/evolution-probe` 的目标版本依赖、标准插件包和配置层；
3. 插件只监听已提交的 `session/event`，遇到 `turn/end` 时追加最小记录；
4. 记录暂时使用逐行 JSON 文件，不引入数据库；
5. 把插件作为本地组合包安装到专用 profile；
6. 运行真实网页会话并核对记录；使用 `sessionPersistence.open(id, 'read')` 与 `handle.read(offset, length)` 补读，结束后关闭句柄；
7. 记录源提交、日志格式/代际；不得调用旧 `readFrom`，不得把未持久化或格式迁移失败的记录当作完整证据。

验收：插件异常不会阻止会话完成；真实记录包含会话标识、事件序号和时间。

### 任务三：网页常驻状态

1. 用创造模式实际查询网页可用界面位置，选最小且不会替换核心区域的位置；
2. 适配浏览器入口：新版不再有 `dsh-client-runtime`，使用目标版本的 Cordis `Context` 与 `dsh-client-ui-renderer/client`，重写旧 SlotRegistry 测试导入和 manifest 依赖；
3. 状态同时使用文字和现有主题的强调样式，不能只改变颜色；
4. 加载插件后检查状态出现；停止或移除插件后检查状态消失；
5. 状态探针先显示“自进化：记录中”，不在此任务加入问题卡片或复杂状态机；旧 `conversation.composer.dock` 在目标源码中仍存在，但须实机核对生命周期。

验收：刷新页面后标记仍存在，并真实随插件生命周期出现和消失。

### 任务四：独立创造模式候选

1. `scripts/run-candidate-probe.mjs` 创建独立 `DSH_HOME`、临时测试 profile、数据目录和工作区，禁止指向真实主 profile；
2. 子进程只继承明确允许的环境变量，并按需要注入 Flash 凭据；
3. 启动目标 Harness 的创造模式，让模型用 `cordis_inspect_list/query` 检查接口，再编写只记录生命周期的标准 bundle（包清单、入口、配置层）；
4. 通过 `plugin_manager` 安装到测试 profile，遵循操作批准与构建脚本批准；验证安装、激活、停用和再次启用。涉及 Client 查询或界面时连接隔离测试页面，不把安装回执当作渲染成功；
5. 保存候选源码、工具调用记录和诊断后清理临时目录；
6. 为整次尝试记录时间和消耗限额，各子步骤共享预算；分别演练超时和消耗达限后的停止、进程清理、证据保留及不自动重试；
7. 不把“独立进程”描述为恶意代码安全沙箱。

补充 D-051 验收：网页触发按需工作进程，工作进程编排独立测试实例；模拟工作进程退出，网页继续可用、状态标记中断且不自动重试；停止请求能清理工作进程及其测试子进程。不先搭完整 CLI。

验收：主网页进程不装载候选；候选失败不改变主进程状态。

### 任务五：标准产物冻结、干净实例复验与重启

1. 冻结任务四的标准候选包、配置和依赖记录，不直接写入正式启用清单；
2. 先检查包清单、插件入口和配置层能够被官方加载器解析；
3. 在新的干净测试实例安装该冻结产物并运行生命周期检查；完整闭环阶段按冻结验证计划复验所有适用离线检查，不统一要求完整任务重放；
4. 标准形态通过后才把它写入测试用启用清单；
5. 重启网页界面并确认插件仍存在；
6. 保留开发版本、冻结产物和验收结果的来源关系，并确认没有候选安装污染真实主 profile；
7. 验证计划发布作用域：Plugin Manager 管理整个 profile，不会替我们保证只影响新会话；preset 挂载或新运行实例路径须实际检查。

验收：冻结产物的结果单独记录，不能用开发中某次运行通过代替。替换已安装包须重启加载新模块。

### 任务六：启动与运行故障恢复

1. 为 `scripts/start.mjs` 写一个可执行自检：测试 profile 启动失败时恢复 `previous.json`，随后只重试一次；
2. 启动器用子进程退出状态和受管理插件集合的激活检查判断结果，网页端口就绪不能单独证明成功；
3. 人为加入无法加载的受管理插件，覆盖进程非零退出，以及网页仍启动但插件激活失败两种情况，确认外部启动器都识别为检查失败；
4. 确认启动器原子恢复上一份清单，第二次启动成功；
5. 保存坏版本、失败输出和恢复记录；
6. 第二次仍失败时明确退出，不无限重启；
7. 在启动成功后，用测试插件注入明确故障使进程退出，验证外部启动器仍能恢复，不依赖控制插件存活；
8. 演练进程仍可运行时的插件故障：受影响任务先暂停，坏插件停止作用后再提示用户；不能只切换新任务的默认清单；
9. 确认恢复不会自动重放中断工具调用；未知原因退出保留诊断并交人工判断，不直接认定插件故障。

验收：即使控制插件未启动或随进程退出，恢复路径仍然存在；恢复后受影响任务保持暂停并提示用户决定如何继续。

### 任务七：最小文件撤销边界演练

仅使用可丢弃工作区，不建设通用备份平台：

1. 记录测试插件操作来源、文件修改前内容、修改后状态和后续改动；
2. 故障后停止相关写入，对归属明确且无后续改动的文件自动撤销并验证结果；
3. 模拟用户或另一正常任务再次修改同一文件，确认整个文件跳过自动撤销，不尝试自动合并；
4. 模拟归属不明或恢复材料缺失，确认保留现场并给出待人工处理清单；
5. 复核撤销时的状态；无法排除并发写入则跳过；验证不整仓恢复、不覆盖无关改动；
6. 保存已撤销、跳过和失败明细。不向真实外部系统试写；不可撤销操作须逐次批准，不纳入自动文件撤销。

验收：撤销已确认的故障修改，同时保住后续正常改动；不能安全撤销的项如实交给用户。

## 4. 执行闸门

| 闸门 | 失败后的动作 |
|---|---|
| 官方固定版本不能启动 | 停止，先修环境 |
| 外部标准插件不能承载会话监听 | 停止，重新评估“不改核心源码”边界 |
| 外部浏览器插件不能稳定显示状态 | 先退回最小官方界面位置，不新建页面 |
| 创造模式无法在独立进程完成候选生命周期 | 停止，不建设候选管理系统 |
| 标准候选不能在干净实例安装或复验 | 不允许正式发布，先解决标准产物与依赖问题 |
| V3 日志读取或旧日志副本迁移失败 | 保留旧版与原数据，停止切换实际运行基线 |
| 测试安装影响主 profile 或旧会话 | 先修环境与发布作用域，不进入正式候选阶段 |
| 外部启动器无法在坏配置下恢复 | 不允许进入真实插件发布阶段 |
| 尝试超限不能停止，或运行故障后坏插件仍在作用 | 先修停止与恢复路径，不继续真实候选执行 |
| 文件撤销会覆盖后续修改，或缺少证据仍自动撤销 | 先修撤销边界，不允许正式插件发布 |

## 5. 明确跳过

- 不做真实经验分类；
- 不调用模型分析长期记录；
- 不做人工练习题；
- 不做问题卡片和候选审查卡片；
- 不做完整六类数据对象；
- 不做自动空闲分析；
- 不做容器平台；
- 不做插件自动合并；
- 不做通用安装器。

里程碑零通过后，先补最小采集、来源标记、任务归并、结果标记和真实状态，再立即开展人工触发的真实发现试验。不要先铺开完整账本、自动空闲调度和审批界面。人工练习闭环与正式发布要求继续按产品设计推进，发现试验不能替代完整验收。

## 6. 下一步：真实发现试验的最小交付

1. 从真实使用中读取按实际任务归并的记录；重试只计一次，人工练习和内部研究排除；
2. 用户仅触发分析，不预先提供问题、根因或修复方案；
3. 系统给出问题、支持任务、相反案例和不确定性，用现有界面命令及结构化报告审查即可；
4. 三个独立真实任务支持的门槛不变；不足就如实记为证据不足，三十个任务时正式复盘；
5. 记录人是否先指出问题：此类改进可验证后使用，但不计入自主发现成果；
6. 发现能力得到验证后再补空闲期自动触发和完整交互；限定范围试用仍须适用检查、批准与恢复；保留决定须报告后续真实效果与证据局限。
